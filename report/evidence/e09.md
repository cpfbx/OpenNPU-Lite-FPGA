# 三后端同场实板诊断：512³主机路径获得实测改善，仍未胜双核ARM

日期2026-10-21；人类负责人/唯一实板操作者/最终批准者bx；准备与本机离线复算Codex/root。
本报告是作者对返回原件的复算，不冒充另一位独立审查人的签名，不申请或宣布默认晋升。

## 1. 结论先行

本次一次固定计划实板完成12块、72调用（48正式、24预热），正常退出和清理通过。
512³完整请求均值由旧FPGA的272.112642 ms降至flat的242.822112 ms，
减少29.290530 ms，即10.764120%，同场旧/新完整请求均值比1.120625×。
这是主机路径最小候选的真实正向结果，不是扣除某段后的反事实预测。

但flat仍慢于本场OpenBLAS 2t的172.240538 ms（均值慢40.978491%）。
256³未改善，flat比旧FPGA均值增加0.692036%，两者均慢于ARM。
因此不能写成“已经战胜双核CPU”“全尺寸加速”或“节能”。

1. **运行时**：冻结链路报告72次逐次全量黄金核对成功；它不是72份完整输出都归档。
2. **本机逐条回读**：48条FPGA指标/输出SHA对固定输入银行，并重算MODE11工作守恒、

4. **独立整数重算**：四组银行（两尺寸×ID42/43）全部用本机INT64矩阵乘法重新计算，

SHA与一致性检查不是对能同时替换全部文件和清单的攻击者的数字签名；

## 5. 本轮512³改善落在哪里（嵌套关系，不全加）

| 计时段 | old均值ms | flat均值ms | 解释 |
| --- | ---: | ---: | --- |
| 完整请求 | 272.112642 | 242.822112 | 同场实测总耗时减少29.290530 |
| 事务构造 | 77.951065 | 78.163881 | 未改善 |
| owned submission | 139.971707 | 111.547700 | 减少28.424007，主要变化所在 |
| └ chain_total | 51.048405 | 49.732968 | 包含下行DMA+PL，不额外加到owned上 |
| └ owned − chain_total | 88.923302 | 61.814731 | 构帧及Owner前后检查合计范围，减少27.108571 |
| 　 └ DMA+PL | 31.045423 | 30.988313 | 仍约31ms；仅约0.057110ms差异，不据此宣称硬件核更快 |
| record重建 | 31.474629 | 31.692842 | 未改善 |
| 输出拆包 | 18.621988 | 17.395977 | 减少约1.226010 |
| 四个外层stage合计 | 268.019389 | 238.800399 | 非完整可加分区，只是四段和 |
| 完整请求减四段和 | 4.093253 | 4.021713 | 保留未归入的差额，不塞给未知函数 |

DMA+PL实际嵌在chain_total内部，而chain_total嵌在owned submission内部；表中缩进只示
包含关系，不能把同级显示误当加总。owned−chain_total是同请求内已知边界间的归因残差，
不是“删掉某段后已达到”的反事实延迟。

本次flat仅替换pack：保留原build_chain_record，直接join header/payload部分，
避免每个record额外物化header+payload中间bytes。原Owner/Call、整链每通道一次DMA与
_submit_chain不变；不把它说成从512次DMA改成一次。
记录没有单独计时pack_chain，因此不能把上述全部差值精确归因给某一次memcpy；
这里只能说变化主要落在构帧/Owner检查合计窗口，与候选改动方向一致。
256³虽owned均值减少约1.408ms，事务构造/拆包等段增加使完整请求未改善，不掩盖该负结果。
