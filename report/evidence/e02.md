## 性能 A/B

比较条件为同板、同 BIT、同种子、同 `BM/BN/BK=64`、同输入输出字节数和同非接收阶段，仅改变 row-major / K-major 布局：

| 指标 | row-major MODE 3 | K-major MODE 5 | 变化 |
|---|---:|---:|---:|
| 512³ 平均墙钟 | 106.6868 ms | **63.9716 ms** | **1.6677×** |
| 有效吞吐 | 1.2581 GMAC/s | **2.0981 GMAC/s** | +66.8% |
| receive cycles / 矩阵 | 4,790,400 | **530,560** | **9.029× 降低** |
| input/output stall | 0 / 0 | 0 / 0 | 无 stall |

K-major 的 receive phase 从 47.904 ms 降到 5.3056 ms，节省 42.5984 ms；clear、array、store、drain、transition 五个非接收阶段逐周期相同。因此这是一项受控的输入布局/接收路径改进，不把其他微架构变化冒充成收益。把 MODE 5 与旧 legacy MODE 1 比较得到的 2.7368×只作为跨模式参考，不能替代上面的公平 1.6677×主结论。

当前 8×8、100 MHz 阵列峰值为 6.4 GMAC/s（按 1 MAC=1 操作计），K-major 墙钟利用率约 32.8%；PL 计数器吞吐为 2.1294 GMAC/s。这里不宣称功耗、能效或跨板性能。

## 应用兼容性与恢复

同一 D006 BIT 在固定 120 条、12 类平衡 KWS 集上完成 baseline/fused 受控 A/B。两条路径均为 `107/120`（`89.17%`），预测变化为 0，所有 Tile 分别与独立 NumPy 黄金模型精确一致。融合路径把输出流量从 `1,572,480 B` 降至 `397,440 B`（`3.9565×`），输入流量增加 `2.93%`；冻结的 accounted inference 口径从 `8.471 ms/样本` 降至 `6.554 ms/样本`，改善 `22.63%`。该口径明确排除 MFCC、Python 编排、打包和黄金检查，因此不得改写成完整 WAV 端到端提速；融合路径 PL total 周期反而增加 `11.17%`，必须一并披露。

恢复测试向 D006 核注入不支持模式 `0x0`，硬件进入 ERROR、返回预期错误码 `0x07`；软复位后状态回到 IDLE、错误码清零，随后 `15×13×17` 随机 GEMM 的 4 个 Tile 和整矩阵均精确。恢复原始记录与机器裁决分别为 `metrics/board_gemm_d006_recovery.json` 和 `metrics/validation_d006_recovery.json`。
